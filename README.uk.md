# StreamList

**Перегляд, редагування та очищення прихованих потоків даних NTFS у Total Commander**

Версія 1.2.1 · Плагін файлової системи (WFX) для 32 і 64 біт · Автор: Native2904 · Ліцензія: MIT

Розділи спираються один на одний: від основ альтернативних потоків даних через роботу з окремими файлами до аналізу цілих дисків за допомогою Everything. Хто вже знайомий зі StreamList, знайде призначення клавіш, поля, а також налаштування й журнал у розділах 5, 10 і 12.

---

## 1. Що таке потік даних?

NTFS зберігає вміст файлу в потоці даних. Крім цього основного потоку, файл може мати скільки завгодно додаткових іменованих потоків – **альтернативних потоків даних** (*Alternate Data Streams*, ADS), далі просто **потоків**. Провідник їх не показує, і відображуваний розмір файлу їх не враховує. Під час копіювання чи переміщення в межах NTFS вони все одно залишаються з файлом.

Найчастіше вони трапляються у вигляді позначки завантаження, яку часто називають *Mark of the Web*: браузери додають до кожного завантаженого файлу потік `Zone.Identifier`. У ньому записано зону безпеки, з якої отримано файл, і зазвичай адресу джерела. На ньому ґрунтується попередження, яке Windows показує під час відкриття таких файлів.

Побачити це можна в командному рядку за допомогою `dir /r`:

| Розмір | Ім'я |
|---:|---|
| 4 858 880 | `alrext.exe` |
| 52 | `alrext.exe:Zone.Identifier:$DATA` |
| 87 552 | `ChmLib.dll` |
| 52 | `ChmLib.dll:Zone.Identifier:$DATA` |

Рядки вигляду `файл:ім'я:$DATA` – це потоки; отже, `alrext.exe` має потік `Zone.Identifier` розміром 52 байти.

StreamList показує ці потоки в Total Commander як звичайні записи, які можна переглядати, редагувати, створювати й видаляти.

---

## 2. Встановлення

Потрібні Total Commander 7.5 або новіший, Windows 7 або новіша та **Everything 1.5** від voidtools з індексованими властивостями потоків (налаштування – у розділі 8). Відкрийте архів у Total Commander і підтвердьте встановлення; після цього StreamList з'явиться в **Мережевому оточенні**.

Розділи 3–7 описують роботу з окремими папками й файлами, розділ 8 – аналіз цілих дисків через Everything.

---

## 3. Перший огляд

Запис **StreamList** у Мережевому оточенні показує диски NTFS системи та два списки зі значком лупи:

| Ім'я | Потоки |
|---|---:|
| 🔍 `! Вільний пошук` | |
| 🔍 `! Усі файли з потоками` | |
| 🔍 `! Завантаження (Zone.Identifier)` | |
| 📁 `C` | ∑ 58 448 |
| 📁 `D` | ∑ 312 |

Списки розглядаються в розділі 8. Спочатку – про те, як виглядають звичайні папки.

---

## 4. Огляд папки

Усередині StreamList папка виглядає як звичайно, і операції з файлами працюють як у звичайній панелі: F5 копіює, F6 переміщує, F8 видаляє справжні файли (розділ 6). Відмінність одна: **Enter на файлі відкриває не сам файл, а його потоки.**

Які файли взагалі мають потоки, показує режим стовпців, який StreamList вмикає під час входу:

| Ім'я | Розмір | Потоки | Вміст | Джерело |
|---|---:|---:|---|---|
| 📁 `Tools` | `<DIR>` | ∑ 31 | | |
| 📦 `setup.zip` | 2 418 330 | 1 | Zone.Identifier | https://example.org/… |
| 📄 `нотатка.txt` | 1 204 | 2 | Comment, один | |
| 📄 `малюнок.png` | 88 112 | | | |

- **Потоки** – кількість потоків у файлу. У папок тут із позначкою `∑` вказано кількість файлів із потоками в усьому піддереві; це значення береться з індексу Everything (розділ 8).
- **Вміст** перелічує імена потоків.
- **Джерело** для завантажених файлів містить адресу з `Zone.Identifier`.

Порожні поля, як у `малюнок.png`, означають, що потоків немає.

Якщо потоки має **сама папка**, угорі додатково з'являється запис `[Streams]`. Про нього розповідає розділ 5.

---

## 5. Список потоків файлу

Enter на `нотатка.txt` відкриває список потоків цього файлу:

| Ім'я | Розмір | Вміст |
|---|---:|---|
| 📄 `Comment.txt` | 7 | Рахунок |
| 📄 `один.txt` | 16 | перший потік |

Стовпець **Вміст** тут показує перший рядок тексту кожного потоку; двійкові потоки відображаються шістнадцятковою послідовністю, наприклад `4D 5A 90 00 …`.

Розширення `.txt` позичене: насправді потоки називаються `Comment` і `один`. StreamList додає його до текстових потоків без власного розширення, щоб після копіювання їх можна було відкрити звичайними програмами. Під час редагування, видалення й перейменування StreamList завжди працює зі справжнім ім'ям. Потоки з розширенням (наприклад, `Zone.Identifier`) і двійкові потоки зберігають своє ім'я; параметр `TxtExtension=0` вимикає цю поведінку.

Робота зі списком потоків ведеться звичними функціональними клавішами:

| Клавіша | Дія |
|---|---|
| F3 | перегляд потоку |
| F4 | редагування потоку – під час збереження він записується назад у файл |
| F5 | копіювати потоки назовні; вони стають звичайними файлами |
| F5 з іншої панелі | копіювати звичайні файли всередину; вони стають потоками |
| F7 | створити новий порожній потік |
| Shift+F6 | перейменувати потік |
| F6 | перемістити потоки назовні |
| F8 | видалити потоки |
| Alt+Enter | відомості про потік |

Backspace повертає до папки. Які правила захисту при цьому діють, описано в наступному розділі.

### Потоки в папок

Потоки можуть мати не лише файли, а й папки. Вони ще менш помітні, ніж потоки файлів, і тому іноді використовуються як схованка. Оскільки Enter на папці веде всередину папки, StreamList показує їх через окремий запис:

| Ім'я | Потоки |
|---|---:|
| 📁 `[Streams]` | 2 |
| 📁 `Підпапка` | ∑ 5 |
| 📄 `нотатка.txt` | 1 |

`[Streams]` з'являється, лише якщо відкрита папка має власні потоки, і веде до звичайного списку потоків з усіма функціональними клавішами. Туди ведуть ще два шляхи: команда `em_StreamListFolder` (розділ 7) для виділеної папки та Alt+Enter на папці з потоками, який пропонує вибір – показати її потоки чи її властивості.

## 6. Правила захисту

StreamList розрізняє два рівні, і функціональні клавіші завжди діють лише на той рівень, який зараз видно:

| Рівень | F5 / F6 / F8 / Shift+F6 діють на … |
|---|---|
| Огляд: папки, списки файлів (розділ 8) | справжні файли й папки |
| Список потоків файлу, списки потоків (розділ 8) | потоки |

Звідси випливають такі принципи:

- **Видалені файли й папки потрапляють до кошика.** У плагінах файлової системи видалення інакше було б остаточним; кошик дає змогу виправити помилку. Самі диски ніколи не видаляються й не перейменовуються.
- **Під час копіювання потоки зберігаються.** Скопійований файл зберігає свої потоки на дисках NTFS.
- **Потоки видаляються лише там, де вони явно показані як потоки.** F8 на файлі видаляє файл – а не окремі його потоки; і навпаки, F8 у списку потоків ніколи не зачепить сам файл.
- **Позначки часу зберігаються.** Запис у потік змінює в NTFS дату зміни файлу; StreamList потім відновлює її.
- **Файли лише для читання** залишаються без змін; StreamList повідомляє причину.

Хто хоче використовувати StreamList виключно як інструмент для потоків, вимикає операції з файлами параметром `FileOperations=0`. Тоді StreamList змінює лише потоки й у разі операцій з файлами в огляді вказує на це налаштування.

## 7. Прямий перехід командою

Для щоденної роботи шлях через Мережеве оточення незручний. Чотири користувацькі команди в `usercmd.ini` (поруч із `wincmd.ini`) ведуть просто в потрібне місце:

```ini
[em_StreamList]
cmd=cd
param=\\\StreamList\%P%N

[em_StreamListDir]
cmd=cd
param=\\\StreamList\%P

[em_StreamListFolder]
cmd=cd
param=\\\StreamList\%P%N\[Streams]

[em_StreamListSearch]
cmd=cd
param=\\\StreamList\!find
```

У розділі *Конфігурація → Налаштування → Різне* їм можна призначити гарячі клавіші; їх також можна розмістити на кнопках.

| Команда | викликана у звичайній панелі на … | Ціль |
|---|---|---|
| `em_StreamList` | файлі | список потоків цього файлу |
| `em_StreamListDir` | будь-якому місці | поточна папка в поданні StreamList |
| `em_StreamListFolder` | папці | потоки цієї папки (розділ 5) |
| `em_StreamListSearch` | будь-якому місці | вільний пошук (розділ 9) |

Команди призначені для звичайної панелі; усередині StreamList достатньо Enter.

Заповнювачі на зразок `%P` і `%N` Total Commander замінює лише в полі **Параметри** команди чи кнопки, але не в полі **Команда**. Якщо все записано там, шлях надходить без змін; StreamList розпізнає це й повідомляє про це.

## 8. Аналіз цілих дисків за допомогою Everything

**Everything 1.5** від voidtools веде індекс усіх файлів системи й уміє шукати в ньому також потоки. StreamList використовує цей індекс для сум ∑ і для списків по всіх дисках, які готові за кілька секунд. Читання, запис і видалення самих потоків StreamList виконує безпосередньо на диску.

### Одноразова підготовка

Щоб Everything міг шукати потоки, потрібно проіндексувати дві властивості (в Everything приблизно в розділі *Сервіс → Параметри → Індекси → Властивості*):

- **Імена альтернативних потоків даних**
- **Кількість альтернативних потоків даних**

Перша індексація триває деякий час; потім Everything сам підтримує індекс в актуальному стані. Якщо властивостей немає, StreamList повідомляє про це, замість того щоб розпочати пошук, який без індексу тривав би кілька хвилин.

### Суми за папками

Значення `∑` з розділу 4 показують, де зосереджені потоки:

| Ім'я | Потоки |
|---|---:|
| 📁 `Users` | ∑ 32 192 |
| 📁 `mingw64` | ∑ 23 044 |
| 📁 `tcmd` | ∑ 961 |
| 📁 `Windows` | ∑ 46 |
| 📁 `Program Files` | |

Великі значення в розпакованих програм на зразок `mingw64` – типові: під час розпакування Windows переносить позначку завантаження ZIP-архіву на кожен файл, що в ньому міститься.

### Списки в корені

Два списки з розділу 3 показують результати пошуку Everything по всіх дисках у вигляді плаского списку.

**`! Усі файли з потоками`** містить кожен файл щонайменше з одним потоком; Enter відкриває його список потоків. Оскільки записи – справжні файли, їх можна копіювати, переміщувати чи видаляти, як у будь-якому списку результатів пошуку.

**`! Завантаження (Zone.Identifier)`** влаштовано інакше: тут кожен запис безпосередньо відповідає `Zone.Identifier` одного файлу.

| Ім'я | Вміст | Папка |
|---|---|---|
| 📄 `__init__.py` | …\winlibs.zip | C:\mingw64\lib\python3.9\asyncio |
| 📄 `__init__ [2].py` | …\winlibs.zip | C:\mingw64\lib\python3.9\collections |
| 📦 `setup.zip` | https://example.org/… | C:\Users\…\Downloads |

Стовпець **Папка** показує розташування; однойменні файли з різних папок розрізняються додатком на зразок `[2]`.

### Видалення позначок завантаження

Оскільки кожен запис цього списку – потік, функціональні клавіші діють безпосередньо: F3 показує позначку, **F8 видаляє її** – навіть для великої кількості виділених записів за один раз, зі звичним підтвердженням та індикатором поступу Total Commander.

Результат докладно:

| | до | після |
|---|---|---|
| Файл | `alrext.exe` | `alrext.exe` – без змін, та сама дата |
| Потік | `alrext.exe:Zone.Identifier` | видалено |
| Windows | попереджає під час відкриття | більше не попереджає |

Позначка виконує захисну функцію. Для надійних програм, розпакованих власноруч, вона не потрібна; для файлів неясного походження її краще залишити.

## 9. Власні списки

Обидва списки – стандартні. У `StreamList.ini` поруч із плагіном можна задати до двадцяти власних пошуків, кожен з яких складається з імені, виразу пошуку Everything і, за потреби, імені потоку:

```ini
[Search1]
Name=! Коментарі (ntfs_diz)
Query=alternate-data-stream-names:comment
Stream=Comment
```

Запис `Stream=` визначає вид списку:

| `Stream=` | Вид списку | Запис – це … | Enter / F8 |
|---|---|---|---|
| порожньо | список файлів | файл | Enter відкриває його потоки; F5/F6/F8 діють на файл |
| задано | список потоків | саме цей потік файлу | F3/F4/F8 діють безпосередньо на потік |

Щойно з'являється розділ `[Search1]`, власні списки замінюють стандартні.

### Вільний пошук

Для змінних запитів – наприклад, потоків-міток на зразок `MyTag` – у корені є запис **«! Вільний пошук»**. Під час входу він показує результати останнього запиту. У самому верху розташований запис **«! Новий пошук…»**: Enter або подвійне клацання на ньому запитує будь-який пошуковий запит Everything; на вибір пропонуються останні десять запитів. Результати з'являються у вигляді списку файлів: F5, F6 і F8 діють на файли, Enter відкриває їхні потоки, а стовпець *Preview* показує вміст потоків. Результати зберігаються до наступного нового пошуку. Просто до списку веде команда `em_StreamListSearch` (розділ 7).

## 10. Власні режими стовпців

Для власних режимів стовпців StreamList надає такі поля:

| Поле | показує … |
|---|---|
| `StreamCount` | кількість потоків; у папок – власні потоки й сума ∑ їхнього вмісту, наприклад `1 · ∑ 5` |
| `StreamNames` | імена потоків файлу |
| `Content` | найкорисніше для кожного рівня: імена, перший рядок або джерело |
| `Origin` | адреса завантаження (HostUrl) |
| `Referrer` | сторінка чи архів, що посилається (ReferrerUrl) |
| `Zone` | Інтернет, Інтранет, Локальний … |
| `Preview` | перший рядок тексту потоку; у файлів і папок – стислий вміст їхніх потоків (без Zone.Identifier), наприклад для потоків-міток на зразок `MyTag` |
| `Kind` | Текст, Двійковий, Відомості про зону, Порожній – або **Програма (EXE/DLL)**, якщо потік містить виконуваний код. Це відома схованка для шкідливих програм, що заслуговує на пильнішу увагу. |
| `Folder` | папка файлу в списках Everything |
| `Size` | розмір файлу чи потоку; у стандартному режимі замінює стовпець розміру Total Commander |
| `StreamsTotal` | сумарний розмір усіх потоків файлу або власних потоків папки |
| `AllocatedSize` | фактично зайняте місце потоку або всіх потоків файлу чи папки |
| `EntryModified` | остання зміна запису NTFS – змінюється, навіть якщо дату зміни файлу збережено |
| `FullStreamName` | повне ім'я у вигляді `C:\…\файл.txt:Comment` |

В огляді папки також доступні поля інших **контентних плагінів**, наприклад ntfs_diz або xytags, оскільки StreamList повідомляє Total Commander справжній файл кожного запису.

Примітка для користувачів тестової версії: Total Commander переймає стандартний режим плагіна лише один раз. Якщо стовпці залишаються порожніми, видаліть збережений режим; під час наступного входу StreamList створить його заново.

---

## 11. Спільна робота з ntfs_diz

ntfs_diz зберігає коментарі до файлів у потоках, кожне поле коментаря – в окремому потоці з ім'ям поля (`Comment`, `Comment1` тощо). Тому в StreamList ці коментарі видно як звичайні потоки, які можна читати клавішею F3 і редагувати клавішею F4. Обидва плагіни можна використовувати одночасно.

## 12. Налаштування й журнал

Налаштування зручно змінювати в діалозі: **клацання правою кнопкою на StreamList у Мережевому оточенні → Властивості.** Він також показує, чи доступний Everything і чи проіндексовано обидві властивості потоків – найчастіша причина, якщо списки залишаються порожніми. Там само можна створювати й змінювати власні списки (розділ 9) та одразу перевіряти їх кнопкою «Перевірити».

Знак **?** у заголовку вікна або **F1** відкриває цей посібник вибраною мовою – одразу на розділі, що стосується вибраного елемента керування. Для цього посібник постачається у вигляді довідки Windows `StreamList_ukr.chm` поруч із плагіном; позначку завантаження цього файлу StreamList під час відкриття видаляє сам, інакше його сторінки залишилися б порожніми.

Після OK StreamList заново зчитує всі налаштування; зміни стають видимими під час наступного зчитування списку (Ctrl+R або зміна папки). Перезапуск Total Commander не потрібен.

**Журнал.** StreamList записує кожну операцію з файлами – з датою, часом, дією, джерелом, ціллю та результатом – у файл `StreamList_operations.txt` поруч із плагіном. Кнопка «Показати журнал…» у діалозі відкриває його у вигляді сортованого списку з фільтром:

| Час | Дія | Джерело | Результат |
|---|---|---|---|
| 2026-10-05 14:03:12 | Потік видалено | `C:\…\setup.zip:Zone.Identifier` | OK |
| 2026-10-05 14:05:40 | До кошика | `C:\Temp\старий.txt` | OK |
| 2026-10-05 14:06:02 | Потік записано | `C:\ADSTest\aa.txt:MyTag` | OK |

Простий перегляд (F3) і тимчасова копія під час редагування (F4) не записуються, а зворотний запис – записується. Файл є текстом із роздільниками-табуляціями; його можна відкрити й у Lister, і в електронній таблиці.

Діалог і файл рівноцінні: усі налаштування зберігаються в `StreamList.ini` поруч із плагіном і можуть змінюватися вручну. Під час першого збереження з діалогу файл переводиться в UTF-16, щоб зберігалися й імена списків, написані нелатинськими літерами.

| Розділ | Запис | Значення |
|---|---|---|
| `[Options]` | `KeepTime=1` | зберігати дату файлу під час зміни потоків |
| | `TxtExtension=1` | показувати текстові потоки без розширення як `.txt` (розділ 5) |
| | `FileOperations=1` | операції зі справжніми файлами в огляді (розділ 6) |
| `[Protocol]` | `Enabled=1` | записувати операції з файлами |
| | `MaxLines=10000` | не більше стількох записів; старі видаляються |
| `[Settings]` | `Language=auto` | мова Total Commander, інакше `eng`, `deu`, `rus`, `ukr`, `dan` |
| `[Everything]` | `Timeout=30000` | чекати на Everything не довше стількох мс |
| | `MaxResults=100000` | не більше стількох записів у списку |
| | `Exclude=!\$Recycle.Bin\` | додається до кожного пошуку; приховує кошик |
| | `FolderQuery=…` | що враховується в сумах ∑; порожньо – вимкнено |
| | `FolderCacheMinutes=5` | скільки хвилин суми використовуються повторно |
| `[Search1]` … `[Search20]` | | власні списки (розділ 9) |

Про `FolderQuery`: служби синхронізації на зразок Dropbox додають до кожного файлу власний потік і тоді домінують у сумах. З `FolderQuery=alternate-data-stream-names:zone.identifier` суми обмежуються позначками завантаження.

## 13. Примітки й обмеження

- Потоки втрачаються, щойно файл копіюється на FAT32 або exFAT, надсилається електронною поштою чи завантажується до багатьох хмарних сервісів.
- Чи копіює Total Commander потоки, визначає параметр `CopyStreams` (див. довідку Total Commander).
- Мережеві диски й CD не показуються в корені, але доступні через `em_StreamListDir`.
- Розміри й позначки часу в стовпцях передаються як текст, бо інакше Total Commander не завжди надійно показує числа в рядках папок. Тому розміри вирівняно праворуч, а час записано у форматі `РРРР-ММ-ДД гг:хх:сс`; так і сортування залишається правильним.
- Суми ∑ беруться з індексу Everything, значення окремих файлів StreamList читає безпосередньо з диска. Одразу після змін вони можуть ненадовго розходитися.
- Якщо Everything не запущено, суми ∑ залишаються порожніми, а списки показують повідомлення. StreamList повторює спробу приблизно через 30 секунд; перезапуск Total Commander не потрібен.

## 14. Пошук несправностей

Для пошуку несправностей є **налагоджувальна версія**. Вона пише журнал у файл `StreamList_debug.log` поруч із плагіном; перший рядок показує, який файл плагіна й який файл налаштувань насправді завантажує Total Commander:

```text
=== DEBUG-Build geladen: C:\…\StreamList.wfx64 | INI: C:\…\StreamList.ini (vorhanden) | Log=1 ===
```

Повідомлення про помилки з цим журналом і коротким описом приймаються через форум Total Commander або GitHub. Звичайна версія не містить коду журналювання.
